# AstroAI

A space-physics tutor in which every number comes from a deterministic physics
engine and every citation is verified in code, so the language model orchestrates
but never asserts a fact on its own.

**Live:** [astro-ai-livid.vercel.app](https://astro-ai-livid.vercel.app) (see [Deployment status](#deployment-status))

## Overview

LLM tutors for engineering subjects tend to produce confident but wrong numbers and
citations that do not exist. AstroAI separates the two jobs: a hand-written agent
loop (plan → tool calls → synthesize) uses Gemini to decide *what* to compute, a
Python science service computes it, and a post-synthesis check confirms every
number in the answer traces back to a tool result. Questions about uploaded papers
go through a hybrid retrieval pipeline whose citations are checked against the real
page range of the retrieved chunk; an answer whose citations all fail verification
is downgraded to a refusal. The system is measured with its own evaluation harness
and k6 load tests.

## Key features

- **Tool-using agent** with Zod-validated arguments, per-tool timeouts, backoff on
  transient failures, a 6-round cap, and the full trace returned with each answer.
- **Deterministic physics engine** (`science/orbital.py`): orbital-mechanics
  formulas the model calls instead of doing arithmetic.
- **ISS pass prediction** from Celestrak TLEs with SGP4 and a hand-written
  TEME → ECEF → topocentric frame chain.
- **Paper Q&A (RAG)**: PDF extraction, section-aware chunking, hybrid
  pgvector + full-text retrieval, and code-verified page citations.
- **Evaluation harness** with golden sets generated by the physics engine, a
  versioned LLM judge, and an 18-case adversarial suite.
- **Production concerns**: Supabase JWT auth, Postgres-backed rate limiting and
  idempotency, Sentry, an admin metrics endpoint, and CI on every push.

## Tech stack

- **Frontend:** React 19, Vite, TypeScript, Three.js, Supabase Auth (deployed on Vercel)
- **API:** Node.js, Express, TypeScript, Zod, `jose` (JWT), `@google/genai`
- **Science service:** Python, FastAPI, `sgp4`, PyMuPDF
- **Data:** PostgreSQL 17 + pgvector (Supabase), `gemini-embedding-001` at 768 dimensions
- **Quality:** Vitest, pytest, PGlite, k6, ESLint, GitHub Actions, Docker Compose

## Results

Every number below comes from a run of the harness in [`evals/`](evals) or from k6,
measured locally against the real services. Sample sizes are small because the
Gemini free tier allows 20 `generateContent` requests per day per model, so 100%
means "nothing failed in this sample", not "nothing fails"
([ADR-007 §9](docs/decisions/ADR-007-eval-design.md)).

**Evaluation (v0.6)**

| Metric | Result |
|---|---|
| Physics accuracy | 100% (3/3 graded; 2 of 6 not reached due to model quota) |
| Retrieval hit-rate | 96% (22/23, hybrid, top_k=6, full gold set) |
| Refusal accuracy | 100% (4/4 unanswerable questions correctly refused) |
| Faithfulness | 100% (LLM judge, judge-v1, 5 answers) |
| Citation correctness | 100% by judge; 5/5 cited a gold page (deterministic check) |

**Retrieval experiment:** hybrid retrieval reached a 95.7% gold-page hit-rate vs.
91.3% for vector-only, and MRR 0.80 vs. 0.76, across 23 labelled questions
([EXP-001](docs/experiments/exp-001.md)).

**Performance (k6 v2.3.0)**

| Path | Result |
|---|---|
| Calculator through the API | 4,449 requests · p50 10.44 ms · p95 14.25 ms · p99 16.02 ms · 0 × 5xx |
| Science engine alone | 4,450 requests · p50 1.64 ms · p95 2.18 ms |
| Agent, end to end | p50 13.0 s · p95 23.6 s (three model calls) |
| Paper ingestion | 20 pages → 65 chunks in 2.7 s |

The API layer is 0.06% of an agent request; latency is dominated by the three LLM
calls ([docs/load-test.md](docs/load-test.md)).

**Tests:** 561 passing: 298 API (113 against real PostgreSQL 17 + pgvector,
in-process), 203 science, 60 evaluation harness.

## How to run

Requires Node ≥ 20 (see `.nvmrc`), Python 3.12+, and a Supabase project. To run
everything locally with no cloud account, follow [docs/local-setup.md](docs/local-setup.md).

```bash
git clone https://github.com/starknight24/Astro-AI && cd Astro-AI

# Environment: values live in per-package env files, never at the repo root
cp .env.example api/.env    # SUPABASE_URL, DATABASE_URL, GEMINI_API_KEY, SCIENCE_URL
cp .env.example web/.env    # VITE_SUPABASE_URL, VITE_SUPABASE_ANON_KEY

# Database: run db/migrations/*.sql in order (Supabase SQL editor, or `npm run migrate` in api/)

# 1. Science service
cd science
python3 -m venv .venv && ./.venv/bin/pip install -r requirements-dev.txt
./.venv/bin/uvicorn main:app --port 8000

# 2. API (new terminal)
cd api && npm ci && npm run dev          # http://localhost:3001

# 3. Web (new terminal)
cd web && npm ci && npm run dev          # http://localhost:5173
```

`docker-compose up` runs the API and science service together.

Try the agent from the command line:

```bash
cd api
npx tsx scripts/agent-cli.ts "Calculate the orbital period of a satellite at 400 km \
  and tell me when the ISS next passes over Toronto"
```

Run the same checks as CI (no network, database or API key needed):

```bash
cd api     && npx eslint src/ scripts/ && npx tsc --noEmit && npm test && npm run build
cd web     && npx eslint src/          && npx tsc --noEmit && npm run build
cd science && ./.venv/bin/pytest -q
cd evals   && ../science/.venv/bin/pytest -q
```

Evaluation and load tests:

```bash
python3 evals/run_physics.py                               # 6-case smoke subset (--full for all 60)
cd api && npx tsx scripts/run-rag-eval.ts --retrieval-only # retrieval only, no generation calls
cd api && npx tsx scripts/adversarial.ts                   # 18 adversarial cases
k6 run load/calculator.js
```

## Design decisions

Each decision is recorded as an ADR with the alternatives considered and the cost accepted.

| ADR | Decision | Tradeoff accepted |
|---|---|---|
| [001](docs/decisions/ADR-001-service-topology.md) | Three services; Python for science | Each physics call pays an HTTP hop (measured at 1.84 ms) |
| [002](docs/decisions/ADR-002-pgvector-vs-pinecone.md) | pgvector over Pinecone | Recall and scale ceiling; index tuning is in-house |
| [003](docs/decisions/ADR-003-deterministic-physics-engine.md) | Deterministic physics engine | A physics bug would also corrupt evaluation grades |
| [004](docs/decisions/ADR-004-authentication.md) | Supabase JWT verified at the API | No database backstop if a route omits the user filter (covered by tests) |
| [005](docs/decisions/ADR-005-agent-loop-and-guardrails.md) | Hand-written agent loop | Three model calls per request set the latency floor |
| [006](docs/decisions/ADR-006-chunking-and-retrieval.md) | Section-aware chunking, hybrid retrieval | Heading detection is heuristic |
| [007](docs/decisions/ADR-007-eval-design.md) | Engine-generated goldens, versioned judge | Small samples; judge shares blind spots with the model |
| [008](docs/decisions/ADR-008-hardening-and-operations.md) | Postgres rate limits, fail-open | A Postgres outage is also a rate-limit outage |

Embeddings use 768 dimensions rather than the model's native 3072 because pgvector
cannot build an ANN index above 2000 dimensions.

## Deployment status

The web app at the link above and the API at
[astro-ai-ri7l.onrender.com](https://astro-ai-ri7l.onrender.com/health) are an
earlier build. The agent, RAG pipeline, rate limiting, metrics and Sentry are
committed but not yet deployed, and the Supabase project the deployment points to
is currently unreachable. The results above were measured locally. See
[docs/DEPLOYMENT.md](docs/DEPLOYMENT.md).

## Next steps

- Reduce agent latency (p50 13 s) by cutting model calls per request; the trigger is recorded in ADR-005.
- Require `WEB_ORIGIN` in production, the one open medium-severity item in the [security review](docs/security-review.md).
- Persist client notes and telemetry; the schema exists but is not wired up.
- Add OCR for scanned PDFs and better equation and table extraction ([findings](docs/rag-ingestion-findings.md)).
- Remove the legacy `POST /api/solve` route, which still asks the model to do physics.
- Redeploy with the restored database and new environment variables.
