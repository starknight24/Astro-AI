# EXP-001 · Hybrid retrieval vs. vector-only

**Date:** 2026-10-01 · **Status:** concluded, decision applied

## Question

The RAG retriever runs two retrievers and fuses them by Reciprocal Rank Fusion:
pgvector cosine top-k, plus Postgres full-text top-k ([ADR-006](../decisions/ADR-006-chunking-and-retrieval.md) §6).
Vector-only is one line simpler, one query cheaper, and the default most RAG
systems ship.

**Is the keyword half earning its place?**

ADR-006 asserted it was, on the argument that academic papers are full of
identifiers that carry no semantics (`NRLMSISE-00`, `NORAD ID 56205`,
`G0.11-0.11`). That was an argument, not a measurement. This experiment measures
it.

## Design

Exactly one variable changes: `hybrid: true` → `hybrid: false`. Everything else
is held fixed — same corpus, same chunk configuration, same embedding model,
same candidate pool, same `top_k`, same gold labels, same code path.

| Held constant | Value |
|---|---|
| Corpus | 3 arXiv astro-ph papers, 54 pages, 163 chunks |
| Chunking | target 1400 / max 2000 / overlap 200 chars |
| Embeddings | `gemini-embedding-001`, 768 dims, re-normalised |
| Candidate pool | 20 per retriever |
| `top_k` returned | 6 |
| Dataset | `rag-golden-v2`, 23 answerable cases (+5 unanswerable, not scored here) |
| Mode | `--retrieval-only` — no answer generation, no judge |

**Why retrieval-only.** Retrieval quality is measurable deterministically
against gold page labels, with no model in the loop. That removes sampling noise
from the comparison *and* costs zero `generateContent` quota, which on this
project's free tier (20 requests/day/model) is the binding constraint. An
experiment that can be re-run at will is worth more than one that can be run
once.

```bash
cd api
npx tsx scripts/run-rag-eval.ts --retrieval-only --label "A: hybrid, top_k=6" \
  --out ../evals/results/exp001-A-hybrid.json
npx tsx scripts/run-rag-eval.ts --retrieval-only --no-hybrid --label "B: vector-only, top_k=6" \
  --out ../evals/results/exp001-B-vector-only.json
```

### Metrics

- **Retrieval hit-rate** — fraction of answerable cases where a gold page falls
  inside a returned chunk's page range. The primary metric: if the page is not
  retrieved, no amount of prompt work can produce a correct citation.
- **MRR** — mean reciprocal rank of the first gold page. Hit-rate alone cannot
  tell rank 1 from rank 6, and rank matters because the answerer sees a limited
  context.
- **Gold page at rank 1** — the blunt version of the same thing.

## Results

| Metric | A — hybrid | B — vector-only | Δ |
|---|---|---|---|
| **Retrieval hit-rate** | **95.7%** (22/23) | **91.3%** (21/23) | **+4.3 pp** |
| MRR | 0.8007 | 0.7645 | +0.0362 |
| Gold page at rank 1 | 16/23 | 15/23 | +1 |
| Misses | `rag-015` | `rag-004`, `rag-015` | −1 |

Hybrid **fixed one case and broke none**.

### The case hybrid fixed

**`rag-004`: *"What service life had been declared for the mission?"*** —
gold page 1, where the FACSAT-2 paper reads *"against a declared service life of
at least five years"*.

| | result | retrieved pages |
|---|---|---|
| vector-only | **MISS** | 5, 9, 15, 17 |
| hybrid | **HIT at rank 1** | 1, 9, 15, 17 |

The mechanism is clear and is the one ADR-006 predicted. The question's wording
("service life … declared") is almost verbatim the paper's own phrase, so
full-text search scores page 1 first. The embedding, meanwhile, drifted to pages
5/9/15/17 — the sections that *discuss* orbital lifetime at length (scenarios,
counterfactuals, lifetime tables). Semantically those pages are about lifetime;
they just do not contain the declared figure. Dense similarity rewarded topical
density over the exact statement.

### The case neither fixed

**`rag-015`: *"What Earth-Moon orbital period does the model assume?"*** —
gold page 3. The fact is a subordinate clause in the opening of §2: *"the Earth
and Moon describe circular trajectories around their barycenter with a period of
27.32 days"*. Both arms retrieved pages about transfer times and times of flight
instead.

Why both fail: "orbital period" is the single most common phrase in a paper
about Earth–Moon transfers, so neither the embedding nor the keyword index can
distinguish *the Earth–Moon system's* period from *the transfer's* period. The
string "27.32" appears exactly once in 24 pages. This is a retrieval-granularity
problem, not a hybrid-vs-vector one, and it is logged as the known miss rather
than papered over.

## Interpretation

Hybrid is better, by a small and explainable margin, with no observed downside.

Three honest caveats:

1. **n = 23.** A +1-case difference on 23 cases is weak statistical evidence;
   the 95% binomial interval on 22/23 comfortably overlaps 21/23. What makes this
   actionable is not the delta's size but that the **mechanism is understood**:
   keyword matching wins when the question reuses the paper's wording, which is
   precisely what a student asking about a named model, instrument or identifier
   does.
2. **It confirms a prior rather than challenging one.** The honest version of
   this result is "the argument in ADR-006 §6 survived contact with
   measurement", not "measurement revealed something surprising". The value is
   that it *could* have gone the other way — and if hybrid had cost accuracy, the
   simpler path was already implemented behind a flag.
3. **Three papers, one domain.** Nothing here generalises to a corpus without
   dense identifiers.

The cost of keeping hybrid is one additional indexed SQL query per question
(GIN index, no model call). Against a 2–5 s end-to-end answer that is noise.

## Decision

**Keep hybrid retrieval on by default.** `hybrid: false` stays available as a
request parameter and a runner flag, so this experiment is repeatable as the
corpus grows.

Two further decisions follow from the run:

- **The gold labels were corrected, once, before these numbers were used.** The
  first baseline (`rag-golden-v1`) reported 87% hit-rate with three misses. One
  of those "misses" — `rag-027`, *"At what confidence level was the redshift
  modulation detected?"* — was labelled `gold_pages=[7]`, but the 95% confidence
  level is stated on **five** pages (1, 4, 6, 7, 10) and the retriever had
  returned two of them. The label was wrong, not the retriever. Rather than fix
  only the inconvenient label, the rule *"a page is gold iff reading that page
  alone answers the question"* was applied uniformly to all 23 answerable cases,
  which **narrowed** 2 labels and **broadened** 10. The dataset is versioned
  `rag-golden-v2` and the rule is recorded in it. This is the methodological risk
  of author-and-measure in one session, and the mitigations are: one stated rule,
  applied to every case, corrections in both directions, and the whole episode
  written down here.
- **`rag-015` is the next retrieval target**, not a bigger `top_k`. A fact
  buried in a subordinate clause is a chunk-granularity problem; raising `top_k`
  would trade precision for a case that smaller chunks or semantic chunking
  (ADR-006's revisit trigger) would fix properly.
